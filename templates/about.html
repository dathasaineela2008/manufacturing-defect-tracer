Academic Problem Statement

"A manufacturer cannot trace which batch or machine produced a defective unit."

MDTPS Solution: Provides deterministic backward and forward lineage tracing from any serialized Unit ID back to its Product catalog specification, Batch production run, Machine shop-floor asset, Production date & shift, and Defect inspection history, backed by mathematical relations and supervised probability prediction.

Relational Database Entity-Relationship (ER) Architecture

3NF Relational Model 
=============================================================================
                          ENTITY-RELATIONSHIP MODEL
=============================================================================

  PRODUCT (1)
     │
     │ 1:M (has many batches)
     ▼
   BATCH (M) ◄──────── M:1 (produced on machine) ──────── MACHINE (1)
     │                                                      │
     │ 1:M (contains serialized units)                      │ 1:M (undergoes maintenance)
     ▼                                                      ▼
PRODUCTION_UNIT (M)                                    MAINTENANCE (M)
     │
     │ 1:0..M (quality inspection logs)
     ▼
   DEFECT (M)

=============================================================================
Cardinality & Referential Constraints:
- PRODUCT (product_id PK, product_name UNIQUE)
- MACHINE (machine_id PK, status CHECK)
- BATCH (batch_id PK, product_id FK -> PRODUCT, machine_id FK -> MACHINE)
- PRODUCTION_UNIT (unit_id PK, batch_id FK -> BATCH, serial_number UNIQUE)
- DEFECT (defect_id PK, unit_id FK -> PRODUCTION_UNIT, severity CHECK)
- MACHINE_MAINTENANCE (maintenance_id PK, machine_id FK -> MACHINE)
=============================================================================
1NF (First Normal Form): Atomic attributes, single-valued cells, unique column names, defined primary keys.
2NF (Second Normal Form): In 1NF and no partial dependencies on composite candidate keys.
3NF (Third Normal Form): In 2NF and zero transitive dependencies ($X \to Y \to Z$ eliminated by separating entities).

OOPJ Object-Oriented Architecture (app/models.py)

Design Patterns
Class Name Parent Superclass OOP Principle Demonstrated Key Responsibility in Project
ProductionEntity abc.ABC Abstraction Abstract base class declaring @abstractmethod def summary(self) and encapsulated ID/name.
Product ProductionEntity Inheritance & Polymorphism Inherits base identity and overrides summary() to format product catalog details.
Machine ProductionEntity Inheritance & Encapsulation Inherits identity and exposes helper method needs_maintenance() based on asset state.
Batch ProductionEntity Inheritance Represents manufacturing run connecting product, machine, date, quantity, and shift.
ProductionUnit object Encapsulation Maintains serialized unit identity, candidate key serial number, and status check method.
Defect object Domain Modeling Encapsulates defect event, classification, severity tier, and detection timestamp.
TraceabilityService object Service Pattern Encapsulates complex multi-table SQL join lineage queries into clean domain methods.
BTree object Algorithmic Data Structure Implements ADSA multi-way search tree with self-balancing node splits.
